# Hadoop and HDFS workflow

This is a genuine Hadoop Streaming path, not the dashboard's local Pandas mode. It
has not been executed in this Windows workspace: Java, Hadoop and Hive are not
installed. Use a supported Linux environment, WSL2, or a separately configured
cluster. Confirm your Hadoop distribution's Streaming JAR location and syntax.

## Prepare and copy data

The sample CSV is for functional smoke tests. For real datasets, check the
dataset's license and remove personal identifiers before transfer.

```bash
hdfs dfs -mkdir -p /socialpulse/input
hdfs dfs -put -f data/sample/socialpulse_sample.csv /socialpulse/input/
hdfs dfs -ls /socialpulse/input
```

## Run the Hadoop Streaming word-count job

Set `STREAMING_JAR` to the Streaming JAR provided by your Hadoop installation.
Use a fresh output directory for every run; Hadoop rejects an existing output.

```bash
export STREAMING_JAR=/path/to/hadoop-streaming.jar
hdfs dfs -rm -r -f /socialpulse/output/wordcount-001
hadoop jar "$STREAMING_JAR" \
  -files bigdata/mapreduce/mapper.py,bigdata/mapreduce/reducer.py \
  -mapper "python3 mapper.py" -reducer "python3 reducer.py" \
  -input /socialpulse/input/socialpulse_sample.csv \
  -output /socialpulse/output/wordcount-001
hdfs dfs -cat /socialpulse/output/wordcount-001/part-*
```

Mapper output is `token<TAB>1`; Hadoop sorts intermediate keys and invokes the
reducer to sum each token. The mapper reads the second CSV column as text and
skips a `post_id`/`id` header. `python bigdata/mapreduce/local_wordcount.py`
exercises the same scripts locally but does not use HDFS or distribute work.

## Hashtag frequency

The hashtag job uses the same reducer and emits one normalized hashtag per
intermediate record:

```bash
hdfs dfs -rm -r -f /socialpulse/output/hashtags-001
hadoop jar "$STREAMING_JAR" \
  -files bigdata/mapreduce/hashtag_mapper.py,bigdata/mapreduce/reducer.py \
  -mapper "python3 hashtag_mapper.py" -reducer "python3 reducer.py" \
  -input /socialpulse/input/socialpulse_sample.csv \
  -output /socialpulse/output/hashtags-001
hdfs dfs -cat /socialpulse/output/hashtags-001/part-*
```

Input CSV convention is `post_id,text,...`; map a different column into that
shape before running the example.

## Sentiment aggregation by date and topic

Prepare a processed CSV with this exact column order:
`post_id,text,timestamp,sentiment,topic`. Sentiment labels must already have
been generated by the analytics pipeline or reviewed label source; this job
aggregates those labels and does not infer sentiment itself.

```bash
hdfs dfs -put -f processed_posts.csv /socialpulse/input/
hdfs dfs -rm -r -f /socialpulse/output/sentiment-001
hadoop jar "$STREAMING_JAR" \
  -files bigdata/mapreduce/sentiment_mapper.py,bigdata/mapreduce/sentiment_reducer.py \
  -mapper "python3 sentiment_mapper.py" -reducer "python3 sentiment_reducer.py" \
  -input /socialpulse/input/processed_posts.csv \
  -output /socialpulse/output/sentiment-001
hdfs dfs -cat /socialpulse/output/sentiment-001/part-*
```

Output is `YYYY-MM-DD|topic|sentiment<TAB>count`. Validate that the sum of
output counts equals the number of valid, non-header input records.

## PySpark transformations

Install the optional dependency and run against a local sample first:

```powershell
python -m pip install -r bigdata/spark/requirements.txt
spark-submit --master "local[*]" bigdata/spark/socialpulse_spark.py `
  data/sample/socialpulse_sample.csv data/spark-output
```

On a configured cluster, stage the CSV in HDFS and use the cluster master:

```bash
hdfs dfs -mkdir -p /socialpulse/input
hdfs dfs -put -f data/sample/socialpulse_sample.csv /socialpulse/input/
spark-submit --master yarn bigdata/spark/socialpulse_spark.py \
  hdfs:///socialpulse/input/socialpulse_sample.csv \
  hdfs:///socialpulse/output/spark-001
```

The job writes word frequency, hashtag frequency, sentiment aggregation, and
normalized posts to separate output paths. Its sentiment calculation is the
same documented English lexicon baseline, not a learned model. `--master
local[*]` is local Spark execution; only the configured cluster invocation
distributes work. Use a new output path for each run.

## Inspect, retrieve, and clean up

```bash
hdfs dfs -ls -R /socialpulse
hdfs dfs -get /socialpulse/output/wordcount-001 ./exports/wordcount
hdfs dfs -rm -r /socialpulse/output/wordcount-001
```

Only remove the specifically named test output. Never use a broad HDFS path.

## Concepts

- NameNode manages filesystem namespace and block locations.
- DataNodes store HDFS blocks and serve reads/writes.
- HDFS splits large files into blocks; replication improves fault tolerance.
- MapReduce maps records to intermediate key-value pairs, sorts/shuffles by key,
  then reduces each key group. Actual distribution depends on a functioning cluster.
